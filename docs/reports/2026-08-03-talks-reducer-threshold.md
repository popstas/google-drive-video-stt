# talks-reducer threshold vs Deepgram STT — результаты

Дата: 2026-08-03. Материал: одна рабочая встреча, 102.8 мин, русский.
Метод и оговорки — в конце; спека: `docs/superpowers/specs/2026-08-03-talks-reducer-threshold-design.md`.

talks-reducer — внешняя программа, применяется к записи до загрузки. В пайплайн
gdstt обрезка не встраивается, и этот замер её туда не тянет: он нужен, чтобы
выбрать уровень для ручного шага.

## Принятое решение

**Использовать `0.01` всегда.** Уровни 0.01–0.03 по качеству неразличимы, и
внутри этого плато выбран самый щадящий: он уже даёт 71% всей достижимой экономии
(15.4 минуты из 21.7 на 0.05), а лишние 3.8 минуты на 0.03 не окупают лишнего
риска — потери уровней не вложены друг в друга, каждый шаг вверх режет свой набор
мест.

Анализ ниже сам по себе указывает на `0.03` как на верхнюю границу плато; выбор
0.01 — это тот же плато, прочитанный в пользу сохранности текста, а не экономии.

- `0.05` **не** «без потери смысла», как казалось на слух: он теряет на ~46%
  больше содержания, чем 0.03 (409 против 280 слов), ради лишних 2.5 минут.
- `0.10` непригоден — подтверждается: WER 19.3%, 887 потерянных слов, 21 крупный
  выпавший фрагмент против 3–6 на остальных уровнях.
- **Бесплатных уровней нет.** Даже 0.01 расходится с необрезанным аудио на 7.6%
  WER и теряет 300 слов. Если точность расшифровки важнее счёта за Deepgram,
  правильный выбор — не обрезать вовсе.

## Что из этого следует

**Гипотеза подтвердилась**: ошибка растёт с агрессивностью монотонно — WER 7.6% →
19.3%, число расхождений 575 → 1167.

**Основная экономия достаётся даром, остальная — дорого.** 0.01 срезает 15.4
минуты — это 71% всего, что вообще можно выиграть на 0.05. Переход 0.01 → 0.05
добавляет всего 6.3 минуты, но поднимает WER с 7.6% до 10.2%. Кривая
«экономия/ущерб» ломается рано.

**0.01–0.03 неразличимы.** WER 7.61 / 7.68 / 8.22%, потерянных слов 300 / 252 /
280 — порядок даже не монотонный. Внутри плато логично брать верхнюю границу,
отсюда 0.03.

**Потери уровней не вложены друг в друга.** Точечная проверка показала фразы,
которые 0.01 потерял, а 0.03 сохранил. Каждый уровень режет свой частично
независимый набор мест, поэтому соседние уровни и «шумят» — это не погрешность
измерения, а свойство обрезки.

**Агрессивность не делает ошибки страшнее — она делает их чаще.** LLM оценила
случайную выборку расхождений: доля `major` держится в коридоре 53–77% на всех
уровнях, включая 0.01, и меняется немонотонно (при n=30 стандартная ошибка ~9
п.п., то есть уровни по этой доле статистически неразличимы). Растёт же **число**
расхождений. Отсюда практический вывод: ранжировать уровни надо по объёму
расхождений, а доля major отвечает на другой вопрос — см. ниже.

**Расхождения настоящие, а не косметические.** Около двух третей случайно взятых
расхождений на любом уровне LLM признаёт потерей смысла, а не разницей пунктуации
или словоформы. Это и оправдывает использование WER как прокси: он здесь меряет
содержание, а не оформление.

**Почему слух обманул.** Пропадают не отдельные звуки, а целые тихие куски по
30–60 слов. Проверено grep'ом по расшифровкам: отдельные характерные слова из
таких кусков присутствуют в orig и отсутствуют в обрезанных версиях, при этом
соседние фразы на месте — то есть выравнивание стоит правильно вокруг реально
пропавшего фрагмента, а не съезжает. Гипотеза механизма (не проверялась): talks-reducer принимает тихую
речь за паузу и сжимает её, после чего Deepgram её уже не распознаёт. При
прослушивании такой кусок мозг достраивает из контекста, а STT — нет.

## Время распознавания

Замер оказался неинформативным: 35 / 45 / 20 / 19 / 19 / 19 / 18 с. Зависимости
от длины аудио нет — orig (102.8 мин) обработался за 35 с, а 0.01 (87.3 мин) за
45 с. Время определяется загрузкой файла и очередью на стороне Deepgram, а не
объёмом распознавания.

Практически значима не задержка, а тарификация: Deepgram считает по минутам
аудио, поэтому экономия равна сокращению длительности — колонка «сэкономлено»
выше, и она точная. Для 0.03 это 18.7% счёта за расшифровку.

## Метод

Все семь файлов прогнаны целиком через боевые настройки (`nova-3`, `ru-RU`,
`diarize_model: latest`, keyterms включены, форматтер `word_speaker`) —
переиспользованы `src.config.load_config()` и `src.stt.get_provider()`, так что
запрос к Deepgram идентичен пайплайновому. Сознательно отключены: перекодирование
через ffmpeg (файлы уже mp3, иначе добавилась бы вторая переменная) и весь
LLM-постпроцессинг.

Сравнение: метки спикеров и таймкоды снимаются, текст приводится к нижнему
регистру без пунктуации, `ё` → `е`; выравнивание через `difflib.SequenceMatcher`
с `autojunk=False` (иначе частотные служебные слова были бы отброшены как шум и
выравнивание развалилось бы).

## Оговорки

- **Эталон — сам Deepgram по необрезанному аудио**, он тоже ошибается. WER меряет
  расхождение с необрезанным прогоном, а не абсолютную точность.
- **Одна встреча, один язык, один состав говорящих.** Вывод индикативный.
- **Предзаданное правило решения не сработало.** В спеке критерием был
  «наивысший уровень с нулём major». Ноль major не получился ни на одном уровне: при подаче
  30 **крупнейших** расхождений LLM ставила major в 26–30 случаях везде, включая
  0.01, потому что крупнейшие блоки по построению и есть худшие места. Выборка
  была заменена на случайную, а ранжирование — на детерминированные метрики
  объёма. Итоговая рекомендация опирается на них, а не на исходное правило.
- **Доля major измерена на n=30 на уровень** и различий между уровнями не
  показывает — использовать её для ранжирования нельзя.
- `SequenceMatcher` — не строгий Левенштейн (ищет длинные совпадающие блоки), так
  что WER может быть слегка завышен. Смещение одинаково для всех уровней, на
  сравнение не влияет.

## Воспроизведение

```bash
uv run python data/results/threshold-tests/run_transcribe.py   # платный, резюмируемый
uv run python data/results/threshold-tests/analyze.py          # --no-llm для метрик без LLM
```

Сырые JSON от Deepgram сохранены в `deepgram_outputs/*.json` — переанализировать
можно без повторной оплаты. Разборы расхождений: `diffs/<уровень>.md` (30
крупнейших) и `diffs/<уровень>.sample.md` (случайная выборка с вердиктами LLM).
