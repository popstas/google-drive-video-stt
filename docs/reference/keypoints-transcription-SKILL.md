# keypoints-transcription

Из произвольной транскрипции (созвон, видео, запись) делает два документа:

1. **`<base> - Транскрипт.md`** - исправленный транскрипт: метки спикеров заменены на реальные имена, лишние метки диаризации склеены, текст реплик сохранён **дословно**.
2. **`<base> - Keypoints.md`** - сводка по транскрипту: Задачи / Тезисы / Открытые вопросы.

Это **самостоятельный** скилл. Не путать с `planerka` (тот заточен под еженедельную планёрку ExpertizeMe: Krisp MCP, папка `Log/Weekly meetings/`, `weekly-report`). Здесь вход произвольный, а главная задача - корректно разобрать спикеров.

## Главная сложность: разбор спикеров

Диаризация часто даёт **больше меток, чем людей** (напр. `Speaker 1/2/3` на двух собеседников). Сопоставление меток с людьми и склейка лишней метки - это работа модели, не скрипта. Скрипт лишь применяет уже принятое решение дословно.

## Шаги

### 1. Вход
- Принять **вставленный текст** ИЛИ **путь/имя файла**.
- Если дано только имя - найти файл в vault: `find . -iname '*<имя>*' -not -path '*/node_modules/*'`.
- Вставленный текст сохранить во временный файл: `/tmp/kp-src-<slug>.md`.
- Определить `base` (для имён выходных файлов) и папку:
  - дан файл → выходные файлы рядом с ним, `base` = имя файла без расширения;
  - вставка → спросить имя/папку у пользователя (дефолт-папка `Notes/YYYY/MM/Video transcription and analysis/`).

### 2. Участники и метки
- Собрать список меток в транскрипте (`Speaker 1/2/3` либо уже именованные `**Andrey | 01:23**`).
- Определить число и имена собеседников: из строки-заголовка (напр. `Yana Banova and Andrey Smirnov`), из контекста реплик, либо **спросить у пользователя**, если непонятно.

### 3. Разбор спикеров (модель)
Сопоставить каждую метку с человеком по содержанию:
- роль и лексика (кто объясняет/коучит, кто отчитывается),
- кого зовут по имени в репликах («Я тебе и пытаюсь объяснить, Андрей» → говорит не Андрей),
- кто инициатор звонка («Алло, …, привет»).

Если меток больше, чем людей - **определить лишнюю метку и к кому её склеить**: к тому собеседнику, чьи фразы продолжает большинство её реплик (диаризатор обычно режет одного человека на куски). Зафиксировать **точечные исключения** - отдельные реплики лишней метки, которые по контексту однозначно принадлежат другому (приветствие/звонок, прямой вопрос собеседнику, короткие подтверждения). Их вынести в `exceptions` по дословному тексту.

### 4. Подтверждение (критично)
Показать пользователю итоговый маппинг и подтвердить через `AskUserQuestion` **до записи файлов**:
- `Speaker N → Имя`,
- какую метку к кому склеили и почему,
- список исключений.

Неверная атрибуция портит оба документа, поэтому шаг обязательный (можно пропустить только если пользователь явно сказал «не спрашивай»).

### 5. Имена → wikilink
Реальные имена привести к нотам `Management/<Имя Фамилия>.md` и обернуть в `[[...]]`. Базовая таблица (та же, что в `planerka`):

| метка/имя | wikilink |
|---|---|
| Irina | `[[Ирина Гольмгрейн]]` |
| Ирина (кириллица) | `[[Ирина Шлыкова]]` |
| Andrey | `[[Андрей Смирнов]]` |
| Stas / Stanislav | `[[Станислав Попов]]` |
| Olga | `[[Ольга Цветцых]]` |
| Olga Andrushenko | `[[Ольга Андрющенко]]` |
| Sasha | `[[Александра Логинова]]` |
| Aleksandr / Alexandr | `[[Александр Арапов]]` |
| Lada | `[[Лада Усольцева]]` |
| Marina | `[[Марина Ларикова]]` |
| Ivan | `[[Иван Коломыцев]]` |

Если ноты на человека в `Management/` нет (проверить `ls`) - оставить имя **обычным текстом** (без битого wikilink), пометить как `unknown` и в финале предложить добавить в таблицу. Не-люди (`AI Receptionist` и т.п.) оставить как есть.

### 6. Исправленный транскрипт
Собрать `MAP.json` и прогнать скрипт - он гарантирует дословность:

```bash
cat > /tmp/kp-map.json <<'EOF'
{
  "header": "# Транскрипт: <Имя1> × <Имя2>\n\n> Исправленная атрибуция спикеров. Speaker 3 → <Имя1>; Speaker 2 и (в основном) Speaker 1 → [[<Имя2>]].\n> Несколько реплик Speaker 1 по контексту отнесены к <Имя1>: \"...\", \"...\".\n> Текст реплик сохранён дословно из исходной расшифровки `[[<исходный файл>]]`.",
  "default": { "Speaker 1": "[[Имя2]]", "Speaker 2": "[[Имя2]]", "Speaker 3": "Имя1" },
  "exceptions": [ { "text": "Алло, ..., привет.", "name": "Имя1" } ]
}
EOF

python3 .claude/skills/keypoints-transcription/relabel_transcript.py \
  --in "<исходный транскрипт>" --out "<base> - Транскрипт.md" --map /tmp/kp-map.json
```

- `default` - метка из транскрипта как есть → итоговое имя/wikilink.
- `exceptions` - дословный текст реплики → имя (перекрывает default).
- Скрипт сам определяет формат (`[HH:MM:SS] Speaker N: text` или krisp `**Label | MM:SS**`), склеивает подряд идущие реплики одного имени, отбрасывает не-реплики (хвосты `## Gemini` и т.п.).
- Неотображённые метки печатаются в stderr (`unmapped labels`) - значит маппинг неполный, дополнить `default`.

### 7. Чувствительные фрагменты
По телу транскрипта (после переименования) проверить маркеры просьбы не сохранять (регистронезависимо): «не записывай / не пиши / вырежи это / убери это / удали из расшифровки / не для протокола / офф рекорд / off the record / между нами / это конфиденциально».

При срабатывании: **не вырезать молча** - процитировать пользователю фрагмент (несколько строк до и после), спросить границы, вырезать только после подтверждения, на месте оставить `<!-- redacted: по просьбе участника -->`. Если маркеров нет - отметить это одной строкой в финальном статусе.

### 8. Keypoints
Из **исправленного транскрипта** собрать `<base> - Keypoints.md`:

```md
# Keypoints: <Имя1> × <Имя2>

Источник: `[[<base> - Транскрипт]]`. <1-2 строки о чём разговор>.

## Задачи
### [[Ответственный]]
- [ ] <задача>

## Тезисы
- <ключевая мысль>

## Открытые вопросы
- <что осталось без ответа>
```

- «Задачи» группировать по `### [[Ответственный]]` (wikilink); имя в самом пункте не дублировать. Непонятен ответственный → `### Без ответственного`.
- «Тезисы» / «Открытые вопросы» - маркеры `-`.
- Без воды и маркетинга. Решения и факты не выдумывать - брать из транскрипта.

### 9. Стиль vault
Соблюдать `expertizeme-vault` / корневой `CLAUDE.md`:
- без длинных тире (—) - вместо них дефис `-`;
- без ёлочек («») - обычные двойные кавычки `"`;
- `Planfix` (не PlanFix);
- wikilink на людей.

Это правило про **мою** разметку (шапка, Keypoints), а не про дословный текст реплик. **В конце проверить оба файла грепом** - частая ошибка:
```bash
grep -c '—' "<file>"        # длинные тире (в шапке/Keypoints должно быть 0)
grep -c '[«»]' "<file>"     # ёлочки (должно быть 0)
```

### 10. Выход и финал
- **tasks.md не трогать** (произвольные транскрипции - задачи не обязательно пользователя).
- Финальный статус: какие файлы созданы, маппинг спикеров (кого с кем склеили), остались ли `unknown`/`unmapped`, были ли чувствительные фрагменты.

## Файлы скилла
- `relabel_transcript.py` - детерминированное переименование + склейка (см. docstring внутри). Не переписывать каждый раз заново.

## Проверка перед ответом
1. В теле `<base> - Транскрипт.md` нет ни одной метки `Speaker N`.
2. Текст реплик дословно соответствует исходнику (скрипт только переименовывает и склеивает).
3. Грепы `—` и `[«»]` по обоим файлам = 0.
4. Wikilink на людей ведут на существующие ноты в `Management/`; кого нет - обычным текстом + пометка `unknown`.
5. Маппинг спикеров подтверждён пользователем (шаг 4).
