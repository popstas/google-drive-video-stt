# Single Agent Skill Bundle Cleanup Design

## Context

The repository currently tracks three complete copies of the `gdstt-cli` Agent
Skill package:

- `skills/gdstt-cli/`
- `.agents/skills/gdstt-cli/`
- `.claude/skills/gdstt-cli/`

The copies are byte-for-byte mirrors generated by `scripts/sync-agent-skills.py`.
The same workflow also copies three maintainer documents from `docs/skills/`
back into the installable bundle. This makes ordinary documentation changes
touch several equivalent trees and leaves room for drift.

The `gh skill` CLI already discovers `skills/*/SKILL.md` packages and installs a
bundle into the correct host-specific directory selected by `--agent`. Codex,
Claude Code, and other supported hosts do not require committed workspace
mirrors when installation is the standard setup path.

## Decision

Keep one complete installable package:

```text
skills/gdstt-cli/
  SKILL.md
  examples/
  references/
```

Remove committed host-specific mirrors and do not replace them with symlinks or
pointer files. Operators install the same package for each host with `gh skill
install`. Host-specific install locations are owned by `gh skill`, outside the
repository.

The bundled files under `skills/gdstt-cli/references/` become the only current
copies of provider notes, troubleshooting guidance, and provider-extension
instructions. Remove the duplicate `docs/skills/` tree and its registry.

## Validation

Keep `scripts/check-agent-skill.py`, but simplify it to validate:

- the canonical bundle exists and has one discoverable `SKILL.md`;
- every bundled resource is routed from the primary skill;
- required references and examples exist;
- example playbooks retain their required sections;
- `gh skill publish --dry-run` passes when `gh skill` is available;
- a temporary local `gh skill install` preserves the complete bundle.

Update `tests/test_skill_docs.py` to assert the same one-bundle contract and to
reject reintroduction of tracked `.agents/skills/`, `.claude/skills/`,
`docs/skills/`, or `scripts/sync-agent-skills.py`.

## Documentation Cleanup

Remove tracked artifacts that are stale or misleading:

- `.claude/settings.json`: contains a machine-specific Linux virtualenv path;
- `docs/plan.md`: superseded initial prototype plan with broken encoding;
- `docs/TODO.md`: completed queue, already represented by completed plans and
  git history;
- `docs/2026-06-01-project-skill-review.md`: migration review superseded by the
  implemented package contract;
- `docs/changelog-30-05-26/`: PR-review notes superseded by git history and
  current docs.

Keep empirical provider research under `docs/deepgram-summary/`, completed
product plans, and historical superpowers specs/plans. They still explain
decisions or preserve implementation history.

## Installation Contract

Use the canonical package for every host:

```powershell
gh skill install . gdstt-cli --from-local --agent codex --scope user --force
gh skill install . gdstt-cli --from-local --agent claude-code --scope user --force
```

The same remote form works after publishing:

```powershell
gh skill install wyrtensi/google-drive-video-stt gdstt-cli --agent codex --scope user
gh skill install wyrtensi/google-drive-video-stt gdstt-cli --agent claude-code --scope user
```
